# Windows 客户端 · Focus Ledger

源码仓库不包含 EXE 或 ZIP；请从仓库 Releases 获取发布附件，或按本文从源码构建。文中的 `release/` 路径表示构建后的本地产物，仓库根目录的 `docs/RELEASING.md` 提供发布指南。

本目录包含 Windows 客户端源码、界面、采集与上传逻辑、测试、预览工具和发布包。服务端单独部署在项目的 `server` 目录。

当前版本 **0.3.1**：修复「同步正在播放的音乐到网页」与启动、设备状态设置重叠，音乐选项独占一行，支持窗口缩放。保留前台变化立即上传，以及协商 gzip 压缩和 500 条补传批次；配合服务端 r10 可实时更新网页。保留程序进度条配色，支持单个 / 全部恢复默认；未设置时自动分配稳定颜色，保存后同步至服务端 r9 的历史时间线和排行。禁用数值框和下拉选择框的滚轮改值，鼠标停在控件上滚动时继续滚动页面；保留手动输入、键盘方向键、增减按钮和下拉选择。配套服务端 r7 在同一账户内按设备名称识别设备，同一电脑升级或重新安装客户端后沿用历史；另一台电脑重名时提示修改名称，改名后缓存继续补传。保留公网 / 内网双地址自动切换，沿用同一账户、设备身份和本地队列。

## 安装与使用

0.3.0 新增「设置 → 同步正在播放的音乐到网页」（默认开启）。开始采集后，每约 2 秒读取 Windows 系统媒体会话，优先展示正在播放的音乐；切歌、暂停、结束时立即尝试上报，失败遵循原上传退避。网页需升级服务端 r12。音乐与前台应用分别读取，切换到其他应用、锁屏或空闲不会把后台歌曲当成停止；暂停采集、睡眠、退出或关闭选项会清除播放状态。不录音、不解析窗口标题，不保存听歌历史。播放器必须支持 Windows 系统媒体控制；部分播放器需在其设置中开启 SMTC / 系统媒体控制，未提供歌名时无法识别。

支持 Windows 10 / 11 x64，无需安装 Python。推荐下载并双击 **`release/FocusLedger-Setup-windows-x64.exe`**，按中文安装向导完成安装：

1. 默认安装到 `%LOCALAPPDATA%\Programs\FocusLedger`，仅供当前 Windows 用户使用，无需管理员权限；可选择其他安装目录。
2. 安装后在开始菜单中打开「专注记录」，也可以在安装时勾选创建桌面快捷方式。
3. 以后运行新版安装包即可覆盖升级，保留配置、上传密钥、设备身份与本地缓存。安装前先从系统托盘右键菜单退出旧程序。
4. 卸载时打开 Windows「设置 → 应用 → 已安装的应用」（Windows 10 为「应用和功能」），找到「专注记录 · Focus Ledger」并选择卸载；也可以使用开始菜单中的「卸载专注记录」。卸载会删除程序、快捷方式及指向该安装目录的自动启动项。

配置和缓存位于 `%LOCALAPPDATA%\FocusLedger`，升级和卸载均保留。需要彻底清除本机数据时，卸载后手动删除这个目录；其中可能包含尚未上传的记录。旧免安装版与安装版共用该目录，安装时已有的免安装版自动启动路径会迁移到安装目录，并保留 Windows 中的启用 / 禁用状态。确认安装版正常后可删除旧免安装程序。

仍可选择免安装版本：

- **单文件版**：直接运行 `release/FocusLedger.exe`，只复制这一个 EXE 即可。首次启动需要解压内置运行库，可能等待数秒；请放到稳定目录后再设置自动启动。
- **文件夹版**：解压 `release/FocusLedger-windows-x64.zip`，运行 `FocusLedger/FocusLedger.exe`；保留整个 `FocusLedger` 文件夹及 `_internal` 子目录，不能只复制其中的小 EXE。解压后的 README 与程序文件夹位于同一级。

所有版本共用 `%LOCALAPPDATA%\FocusLedger` 配置与队列，不要同时运行。单文件版构建输出为 `dist/FocusLedger.exe`，文件夹版为 `dist/FocusLedger/FocusLedger.exe`。

1. 在服务端网页创建用户，并在「账户」页生成该用户的上传密钥。
2. 在客户端「设置」页填写主地址 IP / 域名、端口、HTTP / HTTPS、上传密钥和设备名称；需要内外网切换时，另填备用地址及其协议和端口。
3. 点击「保存设置」（或按 Ctrl+S），通过连接验证后点击「开始采集」。
4. 需要开机启动时勾选「登录 Windows 后自动启动」，然后保存。关闭窗口后程序留在系统托盘，右键托盘可以暂停、上传或退出。

后续启动已配置的客户端会自动采集。暂停采集会停止新增采样，已有队列仍会上传；需要完全停止程序时，从托盘退出。静默模式保留托盘图标，没有可用托盘时会显示主窗口。

`FocusLedger.exe --show` 强制显示窗口，`--silent` 强制托盘启动。程序已在运行（包括静默在托盘中）时再次运行它，会打开已有实例的主窗口。移动程序文件夹后，从新位置运行一次即可自动更新开机启动路径；「自动启动」复选框显示 Windows 的实际状态，在任务管理器中被关闭时会提示，重新勾选保存即可恢复。

### 前台应用变化时立即上传

在「设置 → 采集」中勾选「前台应用变化时立即上传」，再点击「保存设置」。开关默认关闭，原有上传间隔仍默认 30 秒；开启后，每秒检测到切换应用、进入或离开空闲 / 锁屏状态，以及暂停 / 恢复采集时，会额外触发一次后台上传。同一应用保持前台时不会每秒上传，定时上传继续保留。

上传包含刚检测到的应用名称、进程名和状态时间，网页不会继续将刚离开的软件当作当前应用。实时状态不计入使用时长，历史统计仍以本地保存的使用记录为准。断网时使用记录继续缓存在本地，恢复连接后补传，并上报最新前台状态。配套网页支持 SSE：服务端收到上传后通知网页立即更新当前应用，并保留每 10 秒定时校验；实时连接中断后自动重连。

此功能需要同步部署服务端 r10（支持 `foreground` 状态）。连接旧服务端时仍会上传使用记录，并提示「服务端不支持实时前台状态，请升级服务端」；升级服务端后重新保存客户端设置或重启客户端即可启用状态上报。

### 上传流量优化（0.2.9）

当前版本采用紧凑 JSON，补传每包最多 500 条记录。首次上传使用普通 JSON，并从成功响应确认服务端是否支持 gzip；确认后，使用记录、名称翻译和配色同步在请求体达到 256 字节且压缩后更小时自动使用 gzip。连接旧服务端保持普通 JSON；服务器或代理以 HTTP 400 / 415 拒绝压缩时，同一批记录立即用普通 JSON 重试，此连接随后停用压缩，重新保存设置或重启后可再次协商。

保存主题、上传间隔等设置时，已确认且没有改变的名称翻译和配色不会重复同步；修改设备名称、连接或密钥时仍会重新同步，清空映射也会正常提交。上传失败后，自动应用切换遵守原有指数退避（最长 300 秒），等待期间只保留最新前台快照；「立即上传」、保存设置及关机 / 休眠前的限时上传可立即重试。

采样精度、30 秒本地分段、正常上传间隔和空闲心跳保持原样，事件 ID、时间与时长保持原值，离线补传和服务端去重继续生效。压缩需要同步更新客户端 0.2.9 和服务端 r10；本次 `release/` 安装包和 Docker 镜像已包含这些功能。

使用合成记录测量请求体：单条定时上传减少约 29%，已协商压缩的 500 条补传减少约 87%；重启后补传 1,200 条 / 10 小时记录（计入首次普通 JSON）减少约 53%，使用记录上传从 6 次降到 3 次。以上不含请求头、TLS 和失败重试，实际效果取决于数据内容。可在项目根目录执行 `python client/tools/measure_upload.py` 复测。

### 公网 / 内网双地址（0.2.5）

已有公网连接时，保留原「主地址」不变，在「备用地址」填写同一服务端的内网 IP。例如：主地址 `focus.example.com`、HTTPS、443；备用地址 `192.168.1.10`、HTTP、8080。两个地址必须指向同一服务端，使用同一账户和上传密钥；不能用来合并两台独立服务器。

点击「保存设置」后，通过任意一个可用地址完成账户和设备验证即可保存，无需两个地址同时在线。主地址无法连接、超时或返回服务端错误（HTTP 5xx）时，客户端自动尝试另一个地址；后续优先使用最近成功的地址，该地址不可用时再切回。双地址配置下每个地址的连接 / 读取超时为 3 秒；单地址仍为 10 秒。密钥无效、设备冲突、数据校验错误等会直接提示。

上传和历史应用名同步都会自动切换；上传成功状态显示实际使用的地址，「打开服务端网页」也优先打开当前使用的地址。两个地址均不可用时，记录保存在本地，联网后继续补传。添加、修改或删除备用地址不会改变设备身份和缓存归属；主地址仍用于区分不同服务端，因此升级时请将原公网地址保留为主地址。

「服务端」页登录也会自动尝试备用地址。登录后的管理会话固定在登录时的地址；切换网络后管理操作不可用时，退出登录后重新登录即可切换地址，采集上传仍自动切换。通过内网地址生成上传密钥不会覆盖主地址。

备用地址留空即沿用原有单地址行为，旧版配置无需迁移。公网地址应使用 HTTPS，内网 HTTP 适用于可信内网。

### 在客户端管理服务端（0.2.0）

也可以直接在客户端完成账户接入，无需先用浏览器生成密钥：

1. 在「设置」填写服务器 IP / 域名、端口和协议，然后进入「服务端」页。
2. 使用服务端用户名和密码登录。管理员可查看和创建用户、启用 / 停用用户，以及修改数据保留天数（1–365 天）；普通成员只能操作自己的上传密钥。
3. 点击「生成新上传密钥并填入连接设置」，确认后会自动填写密钥、验证账户和设备上传并保存连接。已有密钥会立即失效，其他设备也需更新。
4. 返回「记录」开始采集。管理登录密码与会话只保留在本次进程内；已保存的上传密钥仍使用 DPAPI 加密。

数据保留天数保存到服务端数据库，立即生效并在重启后保留，优先于 `RETENTION_DAYS` 环境变量。缩短保留期会立即清理超期历史记录，客户端保存前会提示。停用用户会退出该用户的全部网页和客户端管理会话，并作废上传密钥；重新启用后需重新生成密钥。

对外端口、绑定地址在服务端 Docker 部署配置中修改，HTTPS 证书在反向代理中配置；客户端会显示这一说明。公网登录和上传均应使用 HTTPS。

「测试连接」会实际发送空上传包，验证上传路径和设备归属，并登记 / 更新设备心跳。切换账户或服务器后再返回，会复用对应的设备身份。需要配套更新后的服务端才能使用管理页；旧服务端仍可按原方式生成上传密钥。

### 设备名称与重名提示

更新至客户端 0.2.6 / 服务端 r7 后，同一账户内按设备名称识别设备，名称首尾空白会被移除。同一电脑升级或重新安装客户端后使用原名称，会沿用服务端原设备和历史记录；不同电脑必须使用不同名称，不同账户之间可以重名。

客户端会发送本机 Windows 系统标识的 SHA-256 摘要，用于区分同一电脑与同名的另一台电脑，不发送原始系统标识。修改设备名称后保存需要联网验证；如果提示「设备名称已被占用，请在设置中修改设备名称后重试」，换一个名称再保存即可。冲突时待上传记录留在本地，改名成功后继续补传。

旧服务端会忽略电脑识别请求头，仍使用旧的设备区分规则；需同时更新服务端才能获得名称识别与重名检查。重装 Windows、克隆系统或复制配置不等同于重新安装客户端，系统标识改变后可能需要使用新设备名称。

### 账户切换与本地缓存

首次保存、更换服务器或密钥、修改设备名称时，需要联网验证账户和设备。已验证且未改变连接的账户，可以离线调整上传间隔等设置。

| 操作 | 设备身份与缓存 |
| --- | --- |
| 同一账户重置上传密钥 | 保留设备 ID 和原队列，更新密钥后继续补传。 |
| 为同一服务端添加公网 / 内网备用地址 | 自动切换时保留设备 ID 和队列；两个地址均不可用时继续本地缓存。 |
| 切换到其他账户或服务器 | 使用对应连接的设备身份，旧队列保留在原连接下，不会发送给新账户或服务器。 |
| 切回原账户和服务器 | 复用原设备身份，继续补传其旧队列。 |

同一设备 UUID 不能同时属于两个账户。清空待上传缓存前会要求确认；本机队列的保留期限与凭据保护见[数据与隐私说明](https://github.com/Mikefuck/I-can-see-you/blob/main/docs/PRIVACY.md#本机凭据与保存位置)。

### 界面

右上角「主题」按钮可选「跟随系统 / 浅色 / 深色」，默认跟随 Windows 的应用主题，系统主题变化时立即更新。手动选择即时保存，无需点击「保存设置」或联网，重新启动后仍有效；不会保存尚未提交的连接或采集设置。服务端网页使用所在浏览器自己的主题选择。

深色预览：[记录页](docs/client-dark-preview.png)、[设置页](docs/client-dark-settings-preview.png)。

窗口顶部始终显示采集状态（红色方块表示正在采集，空心方块表示已暂停）以及「开始 / 暂停采集」「立即上传」两个操作。下方分三页：

- **记录**：今日已记录的时长和一条 24 小时时间轴。深色块（深色模式下为浅色块）是已记录的时间，红色块和红线是正在进行的记录与此刻，▲ / ▼ 标出开机或唤醒、关机或睡眠；鼠标停在色块上可查看应用和起止时间。下面是当前应用、上传状态、待上传缓存、电池状态和最近 50 条记录。
- **设置**：连接、采集选项、应用名翻译和程序配色。保存栏固定在底部；有未保存的修改时，「设置」标签旁出现红色小方块。
- **服务端**：账户登录、生成自己的上传密钥，以及管理员用户管理和数据保留天数设置。

配置、日志与 SQLite 队列保存在 `%LOCALAPPDATA%\FocusLedger`，上传密钥使用当前 Windows 账户的 DPAPI 加密；若密钥无法解密（例如换了 Windows 账户），其他设置保留，只需重新填写密钥。只记录前台应用名称、进程名和使用时间；在设置允许时，也记录电池电量、充电状态以及关机 / 睡眠 / 唤醒节点。不采集窗口标题、截图、键盘输入或文件内容。

### 采集精度与时间显示

- 前台应用约每秒采样，本地使用记录通常按 30 秒分段保存；正常退出会保存当前片段，异常终止可能丢失最近约 30 秒。无法读取的受保护进程会跳过。
- 默认无键鼠操作 5 分钟后暂停计时，可调整阈值或关闭空闲检测；锁屏和休眠仍停止计时。观看视频时可按需要调整空闲阈值。
- 个别格式无效的记录会标为「服务器拒收」并保留在本地，不再阻塞其他记录上传。设备时间超前超过 5 分钟时，服务端会拒绝上传，请先同步系统时钟。
- 客户端记录列表按本机时区显示。网页的时间显示与服务端 UTC 存储规则见[服务端说明](https://github.com/Mikefuck/I-can-see-you/blob/main/server/README.md#时间显示与设备时钟)。

### 电源与电池

- 关机 / 注销和睡眠 / 休眠通知由一个从不显示的系统窗口接收，静默启动时同样有效。事件发生时先把当前使用片段和状态写入本地队列，再限时上传：关机约3秒、睡眠约1.5秒（Windows 只给约2秒）。程序不会阻止关机或睡眠，来不及上传的记录下次联网时补传。
- 唤醒后记录一次恢复节点，并在后台补传，不阻塞界面。
- 电池状态按设置的间隔记录，插拔电源时立即补记；台式机无电池时电量为空。取消「采集并上传电池状态」后，关机 / 睡眠节点中也不包含电池信息。

### 程序名称与颜色（应用名翻译）

按进程名匹配，不区分大小写，可写 `chrome.exe`、`chrome` 或粘贴完整路径。点击「选择系统进程」，搜索当前运行的应用名称、进程名或已有翻译，勾选后可批量添加，再编辑自定义显示名；同名进程合并显示，已有翻译会定位到原行，不会重复添加。列表可刷新，受保护的进程仍显示进程名。

「添加程序」支持手动添加，会预填最近一个还没有翻译的应用；双击最近记录中的应用行也可添加或修改翻译。进程名重复时保存会提示。商店（UWP）应用按实际应用进程（如 `CalculatorApp.exe`）匹配。

同一张表中的「进度条颜色」可为每个程序选择雾蓝、灰青、橄榄等 12 种低饱和配色，色块随客户端深浅色主题调整。显示名可留空，只设置颜色。未指定颜色时，按进程名自动分配稳定的随机配色，网页刷新、程序改名或客户端重启均不会重新抽色。选择「默认」恢复单个程序，点击「恢复全部默认色」清除全部手动配色，再保存设置。

配色按设备同步，保存后用于服务端该设备的今日时间线、历史时间线、当前应用提示、应用排行和使用记录；周 / 月逐日视图按每个时间格中使用最多的程序着色。网页保留原有米色 / 石墨灰和红色时钟标记，深浅色模式使用各自适配的程序颜色。修改不影响原始使用时长；暂停采集时也能同步，离线会在恢复连接后自动重试。程序配色需要同步更新服务端；旧服务端仍可接收记录，手动配色会提示升级。

点击「保存设置」后，客户端立即在后台同步当前设备的翻译，即使暂停采集、没有新记录也会同步。服务端这台设备保留期内的历史记录、时间线、当前应用和应用排行一起使用新名称，其他设备不受影响；原始上传记录、进程名和时长保留，重复上传不会重复累计。断网时设置保存在本机，恢复网络后自动重试，重启客户端后也会继续同步。删除翻译后，历史记录恢复为各条记录上传时的名称。

历史名称同步需要更新配套服务端。旧版服务端仍可接收新记录，但客户端会明确显示「服务端不支持历史名称同步，请升级服务端」。选择框只在本机读取进程名及应用描述，不会把系统进程列表或完整路径上传。

选择框预览：[浅色](docs/client-process-picker-light-preview.png)、[深色](docs/client-process-picker-dark-preview.png)。

## 源码运行与打包

推荐 Windows 10 / 11 x64、Python 3.12 x64。以下命令在本目录执行：

生成安装包还需要 [Inno Setup](https://jrsoftware.org/isdl.php)（推荐 6.7.3 或更高版本），仅构建电脑需要安装。脚本会查找 PATH、常见安装目录及项目的 `.runtime/inno-setup/ISCC.exe`；也可以用 `-Iscc 'C:\工具\Inno Setup 6\ISCC.exe'` 指定编译器。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
.\build.ps1 -Python (Resolve-Path .venv\Scripts\python.exe).Path
```

默认构建文件夹版并生成 **`release/FocusLedger-Setup-windows-x64.exe`**，同时更新 `release/SHA256SUMS.txt`。版本号自动读取 `focus_agent/__init__.py`；固定 AppId 让后续安装包识别同一程序并覆盖升级。中间文件位于 `build`。

- `-Package all`：生成安装包、单文件 EXE 与文件夹版。
- `-Package portable`：仅生成免安装版本，不需要 Inno Setup；可配合 `-Layout onefile` 或 `-Layout onedir`。
- 已有完整 `dist/FocusLedger/` 时，可运行 `./build-installer.ps1` 仅重新生成安装包。

如果 PowerShell 阻止执行本地脚本，可仅对本次进程使用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Python .\.venv\Scripts\python.exe`。

只发布客户端时，在项目根目录执行 `python tools/package_release.py --client-only`，不依赖服务端镜像。若还需发布免安装版本，先用 `-Package all` 构建，再执行 `python tools/package_release.py --client-only --portable`。完成两端构建后也可执行 `python tools/package_release.py` 生成联合发布包。校验安装包：

```powershell
Get-FileHash .\release\FocusLedger-Setup-windows-x64.exe -Algorithm SHA256
```

将结果与 `release/SHA256SUMS.txt` 对照即可。安装版通过安装包升级、通过系统应用列表卸载。免安装版仍通过替换 EXE / 文件夹更新，删除前先取消自动启动并从托盘退出。

## 开发文件

- `focus_agent/`：客户端实现。
- `tests/`：采集、缓存、配置与 GUI 测试。
- `tools/preview_client.py`：使用合成记录生成预览，不采集桌面或发送网络请求。
- `tools/make_icon.py`：生成程序图标（`build.ps1` 打包时自动调用）。
- `tools/build_executable.py`：隔离 DLL 搜索路径后执行 PyInstaller，避免其他软件的运行库混入发布包。
- `build-installer.ps1`、`installer/`：Windows 安装包构建脚本、安装 / 卸载规则与中文向导。
- `docs/`：客户端预览图片。

在项目根目录安装 `tools/requirements-dev.txt` 后，执行 `python -m pytest client/tests`。预览命令为 `python client/tools/preview_client.py`。
