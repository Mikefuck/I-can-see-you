# 接收协议 v1

## 鉴权与连通性

所有设备接口使用请求头：

```http
Authorization: Bearer 用户在网页生成的上传密钥
```

`GET /api/v1/agent/check` 返回：

```json
{"ok":true,"account_id":1,"username":"alice","schema_version":1,"features":["app_usage","device_status","management","app_aliases","app_colors","device_name_identity","foreground"],"retention_days":365}
```

`account_id` 在当前服务器中稳定，用于客户端绑定队列；上传归属以服务端根据密钥查出的用户为准，不信任客户端提供的用户信息。

## 设备名称与电脑识别

服务端按 `(账户, device.name)` 匹配设备，名称去除首尾空白后须为 1–100 个字符，区分大小写。`device.agent_version` 只记录版本，不参与设备匹配；`device.id` 为持久化的客户端 UUID，服务端保留其到设备的映射，供旧队列补传。

上传包和应用名翻译接口支持可选请求头 `X-FocusLedger-Machine-ID`，值须为 64 位小写十六进制摘要。Windows 客户端将稳定的系统 MachineGuid 规范化后，以 UTF-8 对 `FocusLedger/computer/v1|<规范 UUID>` 计算 SHA-256；不上传原始系统标识。其他平台应使用不随客户端版本或重新安装变化的本机标识生成摘要。

同一名称和相同电脑识别值会沿用原设备，即使客户端 UUID 改变；另一台电脑使用相同名称返回 `409 {"detail":{"code":"device_name_conflict","message":"设备名称已被占用，请在设置中修改设备名称后重试"}}`，整次请求回滚。名称在不同账户间互不占用。修改名称需要联网验证，待上传记录使用保存后的名称重试，事件 ID 和内容保持不变。

旧数据库启动时自动归并同账户同名设备，并保留历史与旧 UUID 映射；历史重复事件去重，遇到同 UUID 不同内容时保留两份记录及补传映射。旧设备尚无电脑识别值时，由第一台更新客户端绑定；旧协议无法还原其物理电脑归属。未携带电脑识别值的旧客户端可以继续使用已登记 UUID，但不能用新 UUID 占用已有名称。请求头用于识别设备，账户权限仍由上传密钥决定。

## 同步应用名翻译

`PUT /api/v1/agent/app-aliases` 使用同一上传 Bearer 密钥，正文示例：

```json
{
  "device": {
    "id": "2ad514c4-e596-4ca9-b559-a812a61a8382",
    "name": "我的工作电脑",
    "platform": "windows",
    "agent_version": "0.2.3"
  },
  "app_aliases": {"msedge.exe": "浏览器", "code": "代码编辑器"}
}
```

映射最多 500 条；进程名和显示名均为去除首尾空白后的 1–200 个字符。进程名不区分大小写，完整路径归一为文件名，可省略 `.exe`；完整进程名优先于省略后缀的名称。成功返回 `{"ok":true,"device_id":"…","app_aliases":{…}}`，其中映射为归一化后的完整快照。每次请求替换该设备的整份映射，空对象删除全部翻译，重复请求幂等。

服务端持久保存设备映射，查询时用于该设备保留期内所有历史记录、当前应用、时间线和排行。原始事件、进程名、时长和去重摘要不改写，离线旧记录补传时也使用最新映射显示；删除翻译后显示各条记录上传时的名称。此操作不影响其他设备，无需上传新使用记录；未知设备会按上传规则登记，属于其他账户的设备返回 409，错误密钥返回 401，无效映射返回 422。

客户端保存设置后立即后台同步，失败按上传退避策略重试；映射保存在本机配置中，重启后会再次同步。旧版服务端返回 404 / 405 时，客户端继续上传使用记录，并提示升级服务端。

## 同步程序配色

`PUT /api/v1/agent/app-colors` 使用同一 Bearer 密钥和可选的 `X-FocusLedger-Machine-ID` 请求头，正文为 `{"device":{…},"app_colors":{"msedge.exe":"slate","code":"teal"}}`。设备字段、身份检查和进程名匹配规则与应用名翻译一致；颜色与显示名分别存储，可以只设置颜色。

可选颜色 ID：`slate`、`teal`、`olive`、`ochre`、`terracotta`、`rose`、`mauve`、`indigo`、`steel`、`sage`、`cocoa`、`plum`。这些预设包含适合网页深浅色主题的两套色值，不接受任意 CSS 或十六进制颜色。映射最多 500 条，进程名归一化后须为 1–200 个字符，重复键或无效颜色返回 422，整次请求回滚。

成功返回 `{"ok":true,"device_id":"…","app_colors":{…}}`，映射为归一化后的完整快照；每次替换当前设备的全部手动配色。空对象清除全部手动配色；省略某个进程可单独恢复默认。未覆盖的程序使用规范化进程名（忽略 `.exe`）的 SHA-256 对预设色数取模分配稳定默认色，刷新和重启不变。映射持久保存并用于保留期内历史记录，不改写原始事件或影响去重。客户端保存后后台同步，离线自动重试；旧服务端返回 404 / 405 时继续上传记录并提示升级。

网页看板和个人记录接口保留 `apps` 的 `[显示名, 进程名]` 结构，新增与其索引对应的 `app_colors` 数组，每项为有效颜色 ID。运行片段、时间格、排行和记录的应用索引均引用这组配对数据；同一个程序在不同设备设置不同颜色时会有独立索引。设备的 `last.color` 给出当前 / 最近程序的颜色。周 / 月时间格取使用最多的程序颜色，色深仍表示使用量。

## 上传包

`POST /api/v1/usage/batches`，`Content-Type: application/json`。单包最多500条，压缩前后的请求体均不超过2MiB。空 `events` 列表可用作设备心跳。

当前源码在成功响应中增加可选 `upload_encodings: ["gzip"]`。客户端先使用普通 JSON 上传，确认响应声明后，可对后续上传及应用名翻译 / 配色同步请求设置 `Content-Encoding: gzip`；解压后的 JSON 协议和确认规则不变，不增加能力探测请求。旧客户端忽略此响应字段即可继续使用，未声明支持的旧服务端使用普通 JSON。客户端仅压缩至少 256 字节且压缩后更小的请求。

服务端同时限制线上字节和解压后字节，超出任一限制返回 413；gzip 损坏、截断、尾随数据或拼接多个压缩流返回 400，不支持的 `Content-Encoding` 返回 415。服务端 / 代理以 400 或 415 拒绝压缩时，配套客户端以原事件 ID、原内容进行一次普通 JSON 重试，并在本次连接中停用压缩；保存设置或重启客户端后重新协商。

```json
{
  "schema_version": 1,
  "device": {
    "id": "2ad514c4-e596-4ca9-b559-a812a61a8382",
    "name": "我的工作电脑",
    "platform": "windows",
    "agent_version": "0.1.0"
  },
  "events": [
    {
      "id": "ef4657c4-a932-4644-9633-ea6892f6ac30",
      "kind": "app_usage",
      "app_name": "Microsoft Edge",
      "process_name": "msedge.exe",
      "started_at": "2026-10-09T05:00:00+00:00",
      "ended_at": "2026-10-09T05:00:30+00:00",
      "duration_seconds": 30
    }
  ]
}
```

设备和事件 ID 须为 UUID。`app_usage` 的时间必须包含时区，持续时间须与起止时间匹配且大于0、最多600秒；`device_status` 使用带时区的 `occurred_at`。`platform` 支持小写字母、数字、下划线与连字符，方便其他平台接入；不要求来自 Windows。当前支持 `app_usage` 和 `device_status` 两种事件，不接受未定义的额外字段。

上传包顶层还支持可选的 `foreground` 当前前台状态，须先确认 `/api/v1/agent/check` 的 `features` 包含 `foreground`，以兼容不接受该字段的旧服务端：

```json
{
  "observed_at": "2026-10-16T05:00:01+00:00",
  "since": "2026-10-16T05:00:01+00:00",
  "app": {"app_name": "Visual Studio Code", "process_name": "Code.exe"}
}
```

`observed_at` 为最新采样时间，`since` 为当前应用或无前台状态的起始时间；均须包含时区，`since` 不能晚于 `observed_at`，采样时间不能超前服务端超过 5 分钟。空闲、锁屏、暂停采集时 `app` 为 `null`。同一应用持续使用时更新采样时间、保留起始时间，并随原定时间隔上报；状态变化时立即上报最新快照。

状态与本包使用记录在同一事务中写入，按采样时间保留每台设备最新一份；旧快照重试不会覆盖较新快照，不增加历史记录或累计时长。网页当前应用优先使用有效快照，并应用该设备的名称翻译和配色；过期快照回退到历史记录推断，关闭选项或旧客户端省略 `foreground` 时清除快照。快照随设备删除，并遵守服务端保留期。`foreground` 不使用事件 ID，也不加入 `acknowledged_ids`；使用记录仍按原有规则确认及去重。

`device_status` 用于记录电池状态以及关机、休眠、恢复等生命周期节点：

```json
{
  "id": "04e2e3d3-e1e6-4fd6-bc1a-8dc50d9f4f9e",
  "kind": "device_status",
  "occurred_at": "2026-10-12T05:00:00+00:00",
  "reason": "suspend",
  "battery_percent": 82,
  "charging": false,
  "ac_online": false,
  "battery_life_seconds": 14400
}
```

`reason` 可为 `periodic`、`startup`、`shutdown`、`suspend` 或 `resume`。状态事件与应用使用记录使用同一批次、同一重试和去重规则，但服务端单独存储，不会出现在应用使用排行中。

客户端在生成记录时保存固定事件 ID，重试使用同一个 ID。服务端在一个事务里完成整包入库，同一用户 / 设备 / 事件 ID 不重复累计。

响应示例：

```json
{
  "acknowledged_ids": ["ef4657c4-a932-4644-9633-ea6892f6ac30"],
  "inserted": 1,
  "duplicates": 0,
  "expired": 0,
  "server_time": "2026-10-09T05:00:31+00:00",
  "upload_encodings": ["gzip"]
}
```

`acknowledged_ids` 包括成功插入、已存在和超期丢弃的记录，客户端只删除 / 标记服务端确认的记录。跨越保留期边界的记录仅保存边界之后的部分。

| 状态码 | 含义 |
| --- | --- |
| 200 | 已接受 / 重复已确认 / 超期已丢弃 |
| 401 | 上传密钥错误、被重置或账户停用 |
| 409 | 同账户另一台电脑占用设备名称、设备归属于另一账户或记录 ID 冲突，整包回滚 |
| 413 | 请求大于2MiB |
| 422 | 数据格式无效、持续时间不符、时间不含时区、设备时钟超前超过5分钟 |

`GET /healthz` 不需要鉴权，仅用于容器健康检查，不返回账户或设备信息。

## 网页查看接口

网页与 `/api/web` 查看接口共用可见规则：访客只能读取 `shared=1` 且已启用的账户；有效登录会话可以读取所有已启用账户，包含未公开记录。`shared=0` 表示仅登录成员可见。公开设置按账户生效，停用账户始终不返回。

| 地址 | 访问行为 |
| --- | --- |
| `GET /` | 无需登录，默认显示公开设备看板。 |
| `GET /?view=members` | 显示未公开的成员设备；访客跳转 `/login?next=members`，登录后返回此看板。 |
| `GET /api/web/board?since=…` | 无需登录，按会话筛选可见账户；返回 `authenticated`、`now`、`base`、`apps`、`people`。访客的 `people` 仅含公开账户；登录成员包含所有可见账户，并用 `shared` 区分两个看板。 |
| `GET /api/web/live?username=…` | 返回 `authenticated`、`now` 和可见 `people` 的设备状态、`last` 应用名称 / 进程 / 配色、上报时间；不加载时间线或排行。`username` 可选，指定时只返回该成员；不可见时访客返回 401，登录成员返回 404。 |
| `GET /api/web/events?username=…` | 同源 Cookie 鉴权的 SSE 事件流；遵循相同成员可见规则，推送数据变更通知，由网页重新读取上述 JSON 接口。每页共用一条连接。 |
| `GET /people/{username}` | 公开记录无需登录；访客访问未公开或不存在的账户时跳转登录。 |
| `GET /api/web/people/{username}?start=…&end=…&device=…` | 公开记录无需登录；未登录且账户不可见时返回 401，登录后账户不存在或已停用时返回 404。`device` 可选，必须属于目标账户；时间范围最长 367 天，记录仍受保留期限制。 |

网页、登录页与数据接口统一返回 `Cache-Control: no-store`，公开设置变更会影响后续请求。账户设置、上传密钥生成和管理接口继续要求有效会话，修改操作继续要求 CSRF 校验。

看板与个人记录页通过 SSE 在上传事务提交后读取最新状态。「当前应用」每 10 秒继续读取 `/api/web/live` 作为定时校验和断线兜底；看板历史每 30 秒、个人页当前日每 60 秒、周 / 月每 300 秒、年每 900 秒继续定时刷新。个人页的日期和设备筛选保持不变；前台状态通知只更新实时设备信息，不扫描历史，新增记录通知立即刷新今日看板与个人当天记录。名称 / 配色及可见范围变化还会更新当前打开的历史视图。仅将 `state=active` 的设备列为使用中，读取失败时将旧名称标为「上次上报」。实际延迟仍受客户端采样、上传和网络影响。

事件流响应为 `text/event-stream`，返回 `Cache-Control: no-store` 和 `X-Accel-Buffering: no`。事件包括：

- `ready`：初次连接或重连成功，正文包含 `now`，网页立即重新读取完整快照，补齐断线期间的变化；流声明 `retry: 3000`。
- `changed`：正文为 `{"areas":["live","history"],"now":…}`。`live` 表示设备当前状态，`history` 表示使用 / 电源记录变化，`metadata` 表示名称、配色或保留期变化，`access` 表示可见成员范围变化。通知合并，不包含账户 ID、应用名称或历史正文，私有账户的活动不会向访客推送变更通知。
- `ping`：每 15 秒发送心跳，正文包含 `now`，同时重新检查会话和成员可见性。
- `reset`：会话失效、账户停用或指定成员不再可见，网页关闭连接并重新加载，重新应用权限。

网页使用浏览器自动重连；终止型 HTTP 错误额外按 3、6、12 秒递增重试，最多 30 秒。45 秒没有收到有效消息时主动重建连接；切到后台或离开页面时关闭连接，返回时重新连接并读取快照。原定时请求独立保留，SSE 不可用或浏览器不支持时仍可刷新。

当前 Docker 配置使用单个 Uvicorn worker，通知在该进程内合并，不新增数据库表或 Redis 依赖。多 worker / 多副本部署需另接共享通知机制；定时刷新仍能读取数据库中的最新数据。Nginx 等代理须允许事件流即时转发并关闭响应缓冲，详见服务端部署说明。

## 客户端管理接口（0.2.0）

管理接口前缀为 `/api/v1/management`，使用独立的登录 Cookie 会话，**上传 Bearer 密钥不授予管理权限**。所有请求 / 响应使用 JSON。登录后的修改操作必须携带登录返回的 `X-CSRF-Token`；会话有效期 12 小时。公网使用 HTTPS。

| 方法及路径 | 权限与参数 |
| --- | --- |
| `POST /login` | 请求头 `X-FocusLedger-Client: desktop`，正文 `username`、`password`；返回 `account_id`、`username`、`is_admin`、`csrf`，设置 HttpOnly 登录 Cookie。 |
| `POST /logout` | 当前登录账户，注销当前会话。 |
| `GET /users` | 管理员，返回 `users` 列表，仅含 `id`、`username`、`is_admin`、`enabled`。 |
| `POST /users` | 管理员，正文 `username`、`password`、`is_admin`；新用户默认不公开。 |
| `PATCH /users/{id}` | 管理员，正文 `enabled`；不能停用自己。停用会注销目标用户全部会话并作废上传密钥。 |
| `GET /settings` | 管理员，返回 `retention_days`、只读的 `secure_cookies`、协议版本和管理版本。 |
| `PUT /settings` | 管理员，正文 `retention_days`（整数 1–365）；持久化并立即清理超期数据，返回生效配置。 |
| `POST /token` | 当前登录账户，返回新的 `api_key`、`account_id`、`username`，旧上传密钥立即失效。 |

未登录返回 401；权限不足或 CSRF 不符返回 403；用户名冲突返回 409；字段无效返回 422。端口映射、证书和 Docker 重启不在此 API 的修改范围内。

## 多平台扩展约定

各个平台自行采样前台应用并生成一致的分段记录。设备 ID 在安装时生成并持久保存，不能每次启动重新生成。所有客户端应遵循同样的可见状态、暂停与退出控制，以及断网队列 / 同 ID 重试规则。

添加新记录类型时先定义字段、权限和保留策略，再扩展事件模型、数据库 schema、网页展示与测试。当前接口不会保存任意文件或可执行程序，上传包只包含结构化的应用使用和设备状态 JSON。
