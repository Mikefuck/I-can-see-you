## 验证范围与未覆盖项

历史验证主要使用合成记录、隔离账户与数据库、本机真实 HTTP、临时容器、Qt / Android 框架回归和浏览器检查。

| 范围 | 已记录的验证 | 仍需目标环境确认 |
| --- | --- | --- |
| Windows | 采集与队列逻辑、DPAPI、等效电源消息、原生媒体 API、GUI 与缩放、隔离启动、部分版本的安装 / 升级 / 卸载。 | 真实关机、注销、睡眠 / 休眠、现代待机、登录后启动，以及不同电脑的实际托盘和播放器表现。 |
| Android | 逻辑与 HTTP 联调、API 28 / 30 / 36 的框架回归、原生界面渲染、APK 签名与对齐、构建和 Lint。 | Redmi K90 / 澎湃 OS 3 等真机的权限入口、重启恢复、Doze、厂商后台限制、耗电、播放器兼容及小组件添加 / 缩放 / 后台刷新。 |
| 网页 | Edge 桌面与窄屏布局、深浅色、权限、SSE、时间轴缩放与事件模拟。 | 实体 Android / iOS 手机的多指手感；现有记录未覆盖 Firefox / Safari 的完整验收。 |
| 服务端发布 | Linux amd64 镜像实际导入与运行、Compose、数据卷升级、重建持久化、权限、只读根文件系统和发布包内容核对。 | 目标服务器的公网 HTTPS、反向代理、防火墙、安全组、外部连通性和长时间运行。 |

源码阶段、构建成功、原生渲染和最终设备运行分别记录，不互相替代。部分 Windows 沙箱测试曾受注册表权限、中文或过长临时路径影响；相关版本在正常权限或较短的可写英文路径下复验通过。历史 Starlette / httpx 弃用警告与 Android Lint 警告按各次记录保留，本次文档整理未修复这些警告。

## 连接审核与修复

2026-10-15 的审核针对修复前源码，使用本机真实 HTTP 和合成数据。四项发现已在同日 Windows 0.2.0 / 服务端 r2 修复，并通过上表所列回归与发布验收。

| 最初发现 | 已记录的修复结果 |
| --- | --- |
| 保存期间继续编辑连接，界面内容与实际保存目标不一致。 | 验证期间保护相关输入，保存结果与已验证的连接一致。 |
| 从账户 A 切至 B 再切回 A，生成新的设备 ID。 | 按服务端与账户保存设备身份，返回原连接时复用身份及旧队列。 |
| 同一事件 ID 改变开始时间或时长，仍被误判为重复。 | 补齐内容一致性检查，冲突返回 409，并兼容保留期裁剪后的重试。 |
| GET 密钥检查成功，不能确认上传 POST 路径和设备归属。 | 连接诊断使用空上传批次验证路径与设备，登记 / 更新心跳。 |

后续新增的「服务端」页支持独立管理会话、用户管理、密钥接入和持久化保留期设置。服务器对外端口、绑定地址和 HTTPS 证书仍由 Docker / 反向代理配置，使用方法见 [Windows 客户端](../client/README.md#在客户端管理服务端020)与[服务端教程](../server/README.md#创建用户并连接客户端)。
